# dev-config

Public npm package `@lakestoneai/dev-config`: Lakestone house defaults for code config that every client repo imports. Public on purpose: nothing here may be secret or client-specific (no client names, URLs, ports or data).

| Rule                             | Detail                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One default = one behaviour test | `test/specs/` against real Chromium, written red first; `bun run test` must pass                                                                                                                                                                                                                                                                                           |
| Defaults only, never repo wiring | `playwrightDefaults` sets no `webServer`, `baseURL`, `testDir` or `projects`: Playwright's `defineConfig` concatenates `webServer` and repos own the rest. `defineE2EConfig` is the opt-in e2e harness: it DOES own the `setup`/`chromium`/`mobile` projects, the lanes and the reporters, and still never sets `webServer`, `baseURL` or `testDir` (the repo passes them) |
| Consumers merge defaults first   | `defineConfig(playwrightDefaults, {...repo})`, so a repo's key always wins; don't design anything that needs to override a repo                                                                                                                                                                                                                                            |
| Plain ESM + hand-written `.d.ts` | No build step; `files` in `package.json` is the published surface (check with `bun pm pack --dry-run`)                                                                                                                                                                                                                                                                     |
| Harness tests                    | `test/unit/e2e-*.test.ts` run real Playwright on tiny fixture projects that import the package by name (`test/unit/e2e-harness.ts`): `--list` per lane, resolved config, preflight pass/fail, fixtures with `page.setContent`/routes. No clicks (WSL has no rAF). Mutation-check every new default: flip it and see a test go red                                          |
| Install for testing              | Try an unreleased build in a repo from the `bun pm pack` tarball, never `link:` or a symlink: a link loads `@playwright/test` twice and Playwright refuses to run. `@playwright/test` stays a peer dependency only                                                                                                                                                         |
| Release                          | Bump `version` → push `main` (CI green) → `gh release create v<version> --target main` → `publish.yml` stages it via npm trusted publishing (OIDC, provenance) → a maintainer approves on npmjs.com with 2FA. `bun publish` can't do OIDC or staging, so don't publish locally                                                                                             |
| Semver                           | A tighter default can turn a slow repo's suite red: treat any default change as at least a minor bump and say which repos might need an override                                                                                                                                                                                                                           |
| Renovate preset                  | `default.json` is read by Renovate from the git tag a repo pins (`github>lakestoneai/dev-config#vX.Y.Z`), not from npm. Never add repo-specific keys (`constraints`, `baseBranchPatterns`); validate with `bunx -p renovate@44.216.5 renovate-config-validator --no-global --strict default.json`                                                                          |
| Tests per export                 | `test/unit/*.test.ts` (bun:test) runs the real tool against each export — Prettier formats, ESLint lints, `tsc` compiles a consumer that `extends` the base by package name; Playwright behaviour in `test/specs/`. Every new default gets a test that fails when the default is broken (mutate it to check)                                                               |
| setup-bun action                 | `.github/actions/setup-bun` is used by this repo's own CI (dogfood); callers pin it by SHA. Never `@main`                                                                                                                                                                                                                                                                  |
